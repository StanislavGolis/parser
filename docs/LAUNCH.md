# Dredger 2.0 — план работ до продакшена

Документ отвечает на вопрос «что осталось сделать, чтобы открыть продажи». Составлен
по факту аудита боевого сервера **15.09.2026** (что реально включено, что лежит в БД,
что настроено в `.env`) — не по предположениям. Дополняет
[`Dredger 2.0 — план перехода.md`](Dredger%202.0%20—%20план%20перехода.md)
(фазы и порядок) и [`README.md`](README.md) (техническая документация).

**Обозначения:** `[x]` — сделано и проверено на проде · `[ ]` — осталось ·
`[~]` — сделано частично (есть код, нет финального шага).

## 1. Блокеры запуска продаж

Без этих пунктов продавать нельзя: деньги некуда принимать, а бесплатный доступ
ничем не ограничен.

### 1.1 Тарифы и планы (Фаза 4)
- [ ] Таблица `plans`: `code` (free/month/year/forever), `title`, `days`, `price`,
      `currency`, `is_active`, `sort_order` + миграция.
- [ ] Админка тарифов: список, редактирование цены и срока, включение/выключение
      (без правки кода и `.env`).
- [ ] `GET /api/v1/plans` — что и за сколько (для авторизованных).
- [ ] Тексты: что входит в тариф, правила продления, что происходит при истечении
      (сейчас истечение просто закрывает архив — это надо описать словами).

### 1.2 Free-лимит (5 файлов в сутки)
- [ ] Счётчик просмотров `пользователь × сутки` (Redis с TTL + запись в БД для истории).
- [ ] Логика: пока лимит не исчерпан — файлы открываются; дальше мягкий CTA
      «сегодняшний лимит исчерпан, подписка снимает ограничение».
- [ ] Лимит не действует на собственные закладки и уже открытые в сессии файлы
      (иначе раздражает сильнее, чем стимулирует).
- [ ] В админку: сколько людей упирается в лимит (сигнал спроса на подписку).

### 1.3 Оплата (крипта, без эквайрингов)
- [x] Ручная выдача: `POST /api/v1/admin/users/{id}/premium` — резерв на первую неделю.
- [ ] **CryptoBot (Crypto Pay API)**: инвойс на тариф, проверка оплаты, идемпотентная
      выдача премиума по `invoice_id` (защита от двойного зачёта).
- [ ] Экран в боте: `/subscribe` → тарифы → счёт → «Оплатить» → подтверждение.
- [ ] Журнал платежей `payments` (`user_id`, `plan_code`, `amount`, `provider`,
      `external_id`, `status`, `paid_at`) + вкладка в админке.
- [ ] Возвраты и ошибки: ручная отмена платежа админом с записью в аудит.
- [ ] Telegram Stars — эксперимент, только после обкатки CryptoBot.

### 1.4 Полный пользовательский путь
- [ ] Прогнать на новом аккаунте: канал → бот → `/link` → сайт → лимит → подписка →
      оплата → премиум → архив открыт → истечение (короткий тариф) → архив закрылся.
- [ ] Зафиксировать прогон как приёмку (§6).

## 6. Приёмка перед открытием продаж

Прогон целиком на боевом сервере, с фиксацией результата прямо в этом файле.

**Пользовательский путь**
1. Новичок без аккаунта: пост в канале → бот → `/start` → `/link` → сайт открылся.
2. Free-режим: доступно 5 файлов за сутки, дальше — CTA на подписку; счётчик
   сбрасывается в 00:00 МСК.
3. `/subscribe` → тариф → счёт → оплата (реальная, минимальный тариф) → премиум
   включился без перезахода на сайт.
4. Премиум: доступны `web`, `video`, `raw`, скачивание; закладки и «продолжить»
   работают как ожидается.
5. Истечение (тариф на 1 день): архив закрылся, напоминание пришло заранее.

**Канал и карантин**
6. Автопост: черновик пришёл в ЛС; «Опубликовать» → пост в канале; «Отклонить» → не ушёл.
7. Расписание: пост на конкретное время вышел и корректно удалён.
8. Розыгрыш: анонс → участие из бота (с проверкой подписки) → жеребьёвка → премиум
   победителю выдан → итоги опубликованы.

**Модерация**
9. Жалоба с сайта → `/admin/reports` → файл скрыт, уведомление ушло.
10. CSAM-репорт → файл скрыт автоматически, хеш попал в блок-лист.

**Надёжность**
11. Восстановление БД из бэкапа на отдельной базе — сайт поднялся.
12. Перезагрузка VPS: все сервисы поднялись сами, `healthz: 200`.
13. Мониторинг: остановить `api` → алерт пришёл в Telegram.
14. Мобильный прогон на реальном телефоне (iOS + Android): лента, лайтбокс, свайпы,
    нижнее меню, карточки файлов.

## 7. Порядок и оценка

Порядок выбран так, чтобы блоки не мешали друг другу: деньги → юридика → инфраструктура
→ канал; приёмка — последней.

|---|---|---|---|
| 1 | Тарифы + Free-лимит + `/subscribe` | 2–3 дня | — |
| 2 | CryptoBot: инвойс, выдача премиума, журнал платежей | 3–4 дня | п. 1 |
| 3 | Почта на домене + финальные тексты `/tos`, `/dmca`, `/privacy` | 1–2 дня (+ время на ящик) | доступы к домену |
| 4 | Блок-лист хешей, регламент CSAM, тест модерации | 1–2 дня | — |
| 5 | Бэкапы: выгрузка вне сервера + учение по восстановлению (ежедневный `pg_dump` уже настроен) | 1 день | — |
| 6 | Мониторинг и алерты в Telegram, ротация секретов, перевыпуск токена бота | 1 день | — |
| 6.1 | Мелочи эксплуатации: убрать `dredge-indexnow` из cron, снять расхождение `/opt/dredge` с origin (`prod-state`), освободить build-cache | 0,5 дня | — |
| 7 | Второй бакет, резервный домен и бэкап-канал | 2–3 дня | доступы у владельца |
| 8 | Канал: оформление, контент-план, автопост на реальном трафике | 1–2 дня | п. 1 |
| 9 | Шаг 4 индексации (`Disallow: /`, панели вебмастеров) | 0,5 дня | таймер 2–4 недели |

**Итого до открытия продаж: ~2 недели плотной работы** — без учёта ожидания почты на
домене и таймера индексации, которые идут параллельно.

**Минимальный запуск (если нужно быстрее):** п. 1 + п. 2 + п. 3 (почта и тексты) +
п. 4 (блок-лист) + п. 5 (бэкапы) → приёмка по пунктам 1–5, 9, 11–12 из §6.
Остальное (мониторинг, второй бакет, резервный домен, контент-план) можно догонять
уже на живых продажах.
